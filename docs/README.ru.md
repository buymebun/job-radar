# 📡 Радар вакансий

Юзербот на **отдельном Telegram-аккаунте** (парсере) читает каналы и чаты с вакансиями. Gemini раскладывает каждый пост в карточку (должность, вилка, стек, контакты, тип «работа / проект») и оценивает, насколько вакансия подходит под твой профиль. Всё видно в дашборде на русском. Лучшие вакансии приходят ботом в Telegram, раз в день — дайджест.

- **Только чтение:** радар ничего не пишет от аккаунта-парсера и сам в чаты не вступает (кроме ручного `tools/join_queue.py`).
- **Откликаешься ты:** в карточке есть кнопка «✍️ Черновик отклика», отправляешь со своего личного аккаунта.
- **Весь трафик идёт через отдельный прокси (VPN)** с kill-switch.

## 5. Источники

### 5.1 Папка «Vacancies» (основной способ)
- Добавила канал или чат в папку на **аккаунте-парсере** → примерно через 2 минуты радар его подключил, выгрузил историю за 14 дней, в бот пришло «📥 подключены».
- Убрала из папки → «📤 больше не читаю».
- «Избранное», личные чаты и боты в папке игнорируются.
- Название папки задаётся в `config.yaml → sources.folder`.

### 5.2 Публичные каналы без вступления
`config.yaml → sources.public: ["@username", "https://t.me/username"]`. Радар читает их, не вступая, новые посты забирает раз в 10 минут. Для нового аккаунта это самый безопасный вариант.

### 5.3 Автопоиск
Раз в сутки (и при старте, если давно не искал) радар ищет в Telegram публичные каналы и чаты по запросам `autopilot.search_queries`. Находит до 10 новых, подключает без вступления. Через 4 дня отключает те, где не было ни одной вакансии. Выключить: `autopilot.discover: false`.

### 5.4 Каналы и чаты: в чём разница
- **Каналы:** пост от 80 символов, обычный префильтр.
- **Чаты (группы)** по арбитражу: берутся короткие сообщения (от 20 символов), но только с запросом («ищу / нужен / кто может / в команду…») **и** техническим словом. Те, кто сам ищет работу («ищу работу», «#резюме»), отсекаются. **Контакт — автор сообщения.**

## 6. Дашборд — http://127.0.0.1:8765

- **Вакансии:** таблица с релевантностью, вилкой, форматом, вертикалью, контактами и источником. Фильтры: категория, тип (работа / проект), формат, вертикаль, статус, релевантность от, ЗП от, период. По умолчанию скрыты медиабаинг и продажи.
- **Карточка** (клик по строке): суть, стек, контакты, где встречалась, исходный текст, **✍️ черновик отклика**, статус (Новая → Интересно → Откликнулась → Интервью → Оффер / Отказ / Скрыта), заметки.
- **Источники:** все каналы и чаты, вкл/выкл, сколько постов, вакансий и релевантных.
- **⬇ CSV:** выгрузка по текущему фильтру, открывается в Excel.
- **Шапка:** постов, вакансий, очередь, расход Gemini за сегодня.

## 7. Автономная работа

### 7.1 Сторож
`run_forever.py` держит `run.py` запущенным. Если радар упал, сторож перезапускает его с нарастающей паузой (30 с → 10 мин). Если нет VPN, сторож ждёт и пробует снова, а не уходит в прямое соединение. Лог перезапусков: `data\watchdog.log`.

### 7.2 Автозапуск при входе в Windows
```powershell
powershell -ExecutionPolicy Bypass -File tools\install_autostart.ps1          # установить и запустить
powershell -ExecutionPolicy Bypass -File tools\install_autostart.ps1 -Remove  # убрать
```
Задача называется **JobRadar** («Планировщик заданий»), запускается без окна. Перед установкой нужен хотя бы один ручной вход (`data\parser.session` должен существовать).

### 7.3 Автопилот
- **Каждая вакансия с релевантностью ≥ 80%** (`notify.min_relevance`) приходит ботом сразу.
- **В 10:00 по Алматы** (`autopilot.digest_time`) приходит дайджест: топ новых за сутки, статистика, найденные и отключённые источники.
- **Сигналы:** 6 часов без новых постов (VPN или сессия) и массовые ошибки разбора.

## 8. Сон и крышка ноутбука ⚠️

**Что делает радар сам:**
- **На зарядке запрещает системе засыпать,** пока работает (`power.keep_awake`). Экран гаснет как обычно, а Windows не уходит в сон.
- **На батарее** запрет снимается, чтобы не посадить ноут.
- **После сна догоняет пропущенные посты:** если процесс «пропадал» больше 3 минут, перечитывает все источники с последнего поста.

**Чего программа не может:** переопределить **закрытие крышки**. Если в Windows стоит «при закрытии крышки — сон», ноут уснёт и радар остановится до пробуждения.

Чтобы радар работал с закрытой крышкой (на зарядке):
1. Панель управления → Электропитание → **«Действие при закрытии крышки»**.
2. **«От сети»** → «Действие не требуется». Для батареи оставь «Сон».
3. Сохранить.

Или одной командой в PowerShell от администратора:
```powershell
powercfg /setacvalueindex SCHEME_CURRENT SUB_BUTTONS LIDACTION 0; powercfg /setactive SCHEME_CURRENT
```
Вернуть «сон при закрытии крышки от сети»: та же команда с `1` вместо `0`.

> Ноут с закрытой крышкой на зарядке греется сильнее. Ставь его на твёрдую поверхность, не на кровать.

Если нужен по-настоящему круглосуточный радар без ноутбука — дешёвый **личный** VPS: код тот же, запуск через `run_forever.py`. Не на серверах работодателя.

## 9. Отдельное VPN-подключение (прокси)

- Через `PROXY_URL` идут Telegram, Gemini и бот уведомлений. Остальная система не затрагивается. Локальная Ollama ходит напрямую.
- **Kill-switch:** если прокси не отвечает, радар не стартует и не уходит в прямое соединение.
- При старте в лог и в бот пишется **IP выхода**. 
- DNS тоже идёт через прокси.
- **Не жми «Сменить IP» у прокси без нужды:** Telegram подозрительно относится к сессии, которая прыгает между IP.
- **Трафик:** радар качает только текст сообщений, без медиа. Если прокси оплачивается по трафику, раз в несколько дней смотри расход в панели.

## 9.1 Дашборд в домашней сети (телефон, другой ноут)

- В `.env`: `WEB_HOST=0.0.0.0`, `PUBLIC_URL=http://192.168.1.X:8765`, `DASH_USER`, `DASH_PASSWORD`.
- С других устройств открывать **http://192.168.1.X:8765**, браузер спросит логин и пароль. С самого ноута пароль не спрашивается.
- Ссылки «открыть» в уведомлениях бота ведут на `PUBLIC_URL`, поэтому открываются с телефона, если он в той же Wi-Fi.
- **Брандмауэр** (один раз, PowerShell **от администратора**), правило только для частной сети:
  ```powershell
  New-NetFirewallRule -DisplayName "Job Radar dashboard (LAN)" -Direction Inbound -Protocol TCP -LocalPort 8765 -Action Allow -Profile Private
  ```
- Wi-Fi в Windows должен быть «Частная сеть» (Параметры → Сеть → свойства Wi-Fi). В публичных сетях (кафе) порт закрыт.
- **Адрес ноута может смениться** после перезагрузки роутера. Закрепи его в роутере: «DHCP-резервирование» для этого ноута на `192.168.1.X`. Иначе поменяй `PUBLIC_URL`.
- Снаружи дома (из интернета) дашборд недоступен, и так и должно быть.

## 10. Что подходит, а что нет: `profile.md` и `config.yaml`

- **`profile.md`:** кто ты, что ищешь (роль, вилка, формат), что не подходит. Шаблон: `profile.example.md`. Блок «Факты для откликов» — только эти факты попадают в черновики. Правки подхватываются сразу.
- **`config.yaml`:**
  - `prefilter.plus` / `minus`: слова, которые пропускают или отсекают пост ещё до LLM;
  - `prefilter.chat_request_markers` / `chat_offer_markers`: фильтр для чатов;
  - `collect.backfill_days`: глубина истории (14);
  - `notify.min_relevance`: порог мгновенных уведомлений (80);
  - `autopilot.*`: автопоиск, дайджест, сигналы;
  - `llm.chain`: модели по порядку (Gemini → Groq → Ollama) и суточный лимит Gemini (430);
  - `power.*`: сон.

  После правки `config.yaml` нужен перезапуск.

## 12. Диагностика

| Симптом | Что проверить |
|---|---|
| Радар не стартует, в логе `прокси … не отвечает` | VPN или прокси упал или истёк, проверь данные в `PROXY_URL` (kill-switch сработал правильно) |
| `Нет авторизованной сессии` | сессия слетела → `tools\stop.ps1`, потом `python run.py` вручную и войти заново |
| В бот пришло «6 ч ни одного поста» | VPN, сессия, или источники молчат (ночью это нормально для мелких каналов) |
| Вакансии есть, но все с низкой релевантностью | источники не из твоей сферы: смени каналы в папке или поправь `profile.md` |
| Медленный разбор (~минута на пост) | кончилась квота Gemini, работает Ollama; утром восстановится |
| Ошибка `ZoneInfoNotFoundError` | `uv pip install -p .venv\Scripts\python.exe tzdata` |
| Дашборд не открывается | `tools\status.ps1`: запущен ли процесс, не занят ли порт 8765 |

Логи:
- `data\radar.log`: работа, ротация по 2 МБ;
- `data\watchdog.log`: перезапуски.

## 13. Безопасность

- `data\parser.session` даёт **полный доступ к аккаунту-парсеру**. Никому не отправляй, в git не клади (`.gitignore` настроен).
- `.env` содержит ключи и пароль прокси. Только локально. Если что-то засветилось:
  - бот: @BotFather → `/revoke`;
  - `api_hash`: my.telegram.org;
  - прокси: «Изменить пароль» в панели.
- Дашборд слушает только `127.0.0.1`, снаружи недоступен.
- Аккаунт-парсер **ничего не пишет**. Откликайся с личного аккаунта.

## MCP-сервер для ИИ-ассистента

`mcp_server.py` даёт ИИ-ассистенту (любому MCP-клиенту) доступ к радару: `list_vacancies`, `get_vacancy`,
`save_draft`, `set_status`, `set_contacts`, `list_cvs`, `tracker_read`, `tracker_upsert`, `open_chat`.

Подключение через `.mcp.json` в рабочей папке:

```json
{"mcpServers": {"job-radar": {"command": ".venv\Scripts\python.exe",
                              "args": ["D:\Projects\job-radar\mcp_server.py"]}}}
```

Папка с CV и трекером задаётся `CV_ROOT` в `.env` (по умолчанию папка `cv` рядом с проектом).

## Резюме соискателей (другая сторона рынка)

Посты-резюме (#резюме, «Обо мне… Ожидания по зарплате…») не идут в разбор вакансий, а сохраняются в таблицу resumes: роль, уровень, ожидания, стек достаются правилами, затем локальная модель (Ollama) в фоне уточняет роль, уровень, опыт и пишет одну строку описания. Квоту Gemini это не тратит. Страница /resumes с фильтрами; на /market блок «спрос против предложения» по стеку. Курсы для пересчёта ожиданий в USD: config.yaml → market. Отключить фоновую модель: market.resume_llm: false.
